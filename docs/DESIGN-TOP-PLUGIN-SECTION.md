# 顶部插件区设计

## 背景

DSH 将全局插件面板列表放在工作区/会话浏览区之后。插件数量增加后，常用入口需要向下滚动才能访问。`dsh-pin` 已负责面板行置顶、注册顺序恢复和 React 重渲染后的顺序自愈，因此由它统一调整这份列表的位置。

## 目标

- 将完整 `sidebar.panellist` 移到工作区/会话浏览区上方。
- 页面中只保留一份插件列表；置顶项继续排在同一列表最前。
- 插件区可收起并记住状态，展开时限制高度并独立滚动。
- 保留面板徽标、倒计时、自定义行内容、当前面板高亮和图钉交互。
- DSH 自身折叠为 rail 时继续显示原生面板图标。
- 宿主 DOM 不满足已验证契约时保持原布局，不破坏侧边栏。

## 交互

展开的侧边栏依次显示：宿主顶部操作、插件区标题、插件列表、工作区/会话列表、宿主底部操作。

- 标题使用“插件 / Plugins”，显示当前面板数量和展开箭头。
- 点击标题或按 Enter/Space 切换展开状态，按钮暴露 `aria-expanded`。
- 首次使用时，常规桌面视口默认展开，窄视口默认收起；用户选择写入本地存储并优先于默认值。
- 展开后的插件列表最大约占侧边栏高度三分之一，超出时只滚动插件列表。
- 列表下方提供一条拖拽条，用户可上下拖动调整高度上限，方向键微调、双击复位；高度按浏览器记忆。收起或 rail 时拖拽条隐藏。
- 收起插件区不会切换或关闭当前主面板。
- DSH 进入 rail 时隐藏插件区标题并强制展示原生面板图标；重新展开后恢复用户选择。

## DOM 策略

复用宿主原生 `nav[class*="panelList"]`，不克隆面板行，不创建第二套入口。

1. 找到面板 `nav` 与工作区行共享的父容器。
2. 只有当 `nav` 是该父容器的直接子元素、工作区分支也可明确定位时，才移动 `nav`。
3. 在原位置留下隐藏的 origin marker，用于卸载和契约失效时恢复。
4. 在工作区分支前插入插件区标题和原生 `nav`。
5. React 重挂、插件注册变化和窗口尺寸变化后重新校验并同步。

任何条件不满足时，移除插件区标题并把 `nav` 放回 origin marker 后，现有面板置顶能力继续工作。

## 状态与兼容性

- 新状态键：`dsh-pin.panel-section.v1`，值为 `expanded` 或 `collapsed`。
- 面板置顶仍使用 `dsh-pin.panels.v1`，不迁移、不清空现有数据。
- 插件卸载时恢复 `nav` 原位置、移除标题和新增样式/属性。
- 对 `prefers-reduced-motion` 不添加折叠动画，避免列表重排时产生额外位移。

## 验收标准

- 完整插件列表位于工作区列表上方，且每个入口只出现一次。
- 展开、收起和刷新后状态正确；窄视口首次默认收起。
- 插件置顶、取消置顶、徽标和自定义行内容保持正常。
- DSH rail 中面板图标保持可用，插件区标题不可见。
- 键盘可操作标题，焦点样式清晰，`aria-expanded` 与可见状态一致。
- DOM 契约不满足或插件卸载后，列表安全恢复到原位置。
